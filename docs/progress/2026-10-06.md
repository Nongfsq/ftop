## Issue 1: M5 Pro, CPU unavailable (2026-10-06)

- Cause: only cluster types 'P' and 'E' were accepted, and one unrecognised core made
  the whole CPU reading unavailable. An M5 Pro has ten 'M' and five 'P' cores.
- Change: any type letter is read; groups and names come from the kernel's performance
  levels (`CoreTopology`, FtopCore); a core without a type is still shown. Frequency
  tables are picked per core by step count instead of two fixed table numbers.
- Verified on an M4 Pro: `scripts/check.sh` (36 tests), `ftop doctor` all ok, same
  cores and frequencies as before.
- Verified on an M5 Pro by the reporter with 0.1.1 (2026-10-07, issue 1): `ftop doctor`
  all ok, "5 super + 10 performance cores", all 15 frequencies read. Channels are
  `PCPU0`–`PCPU4` (table 5, 20 steps, 1308–4608 MHz) and `MCPU00`–`MCPU04`,
  `MCPU10`–`MCPU14` (table 22, 15 steps, 1344–4380 MHz; table 23 holds the same
  frequencies). The GPU tables there have 13 steps, so no table fits by accident.
